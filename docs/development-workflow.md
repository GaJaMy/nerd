# 문서 기반 구현 절차

요구사항을 추가하거나 변경할 때 다음 순서를 지킵니다.

1. 사용자 요청을 기존 제품 범위와 비교하고 관련 요구사항·화면 흐름·도메인·상태·디자인 문서를 먼저 갱신합니다. 미정 사항을 임의로 확정하지 않습니다.
2. `.agents/context/07-roadmap-and-priorities.md`에 새 작업의 순서, 범위, 검증 방법, 상태를 기록합니다. 기존 완료 이력과 새 작업을 구분합니다.
3. **갱신이 끝난 문서들을 다시 읽습니다.** 작성 전 읽었던 내용이나 기억만으로 구현을 시작하지 않습니다. 문서 간 충돌이 있으면 먼저 수정하고 다시 읽습니다.
4. 07번 문서의 순서대로 한 작업 단위를 구현합니다.
5. 해당 단위의 포맷·린트·타입·관련 테스트를 검증하고, 주요 UI 흐름은 브라우저 테스트로 확인합니다. 실패를 해결한 뒤 완료 상태를 갱신합니다.
6. 완료한 작업 단위를 한국어 커밋으로 남긴 뒤 다음 작업으로 이동합니다. 검증되지 않은 변경을 완료로 표시하지 않습니다.
7. 새 요구사항이나 수정 지시가 들어오면 필요한 문서와 작업 순서를 먼저 갱신하고 재독한 뒤 이어서 진행합니다.
8. 마지막에 전체 검증, 로드맵 상태, 사용 설명서, Git 작업 트리를 확인합니다. 제외·보류 범위와 실제 검증하지 못한 부분은 구분해 보고합니다.

`.agents/context`는 이 저장소의 기존 Git 제외 정책을 유지합니다. 공유해야 할 요구사항과 개발 절차는 `docs/`에 기록하여 커밋하고, 로컬 컨텍스트에서는 해당 문서를 연결합니다. 문서 변경을 위해 기존 제외 정책을 임의로 변경하지 않습니다.
